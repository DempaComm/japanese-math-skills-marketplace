# 日本語TeXと検証

既存文書のエンジン、文書クラス、文献方式を先に読む。
原稿の言語が日本語だからという理由だけで pLaTeX・upLaTeX から LuaLaTeX へ移行しない。
コーパスのプリアンブルをテンプレートとしてコピーしない。古い命令や空の package 宣言も含まれる。

新規文書では利用できる環境を確認して日本語対応クラスを選ぶ。例えば LuaLaTeX と jlreq は候補であり固定要件ではない。
定理環境と証明見出しを「定理」「命題」「補題」「系」「定義」「例」「注意」「証明」にする。
既存の定理番号、ラベル、マクロ、引用キーを保持する。

本文中の数式は `$...$`、番号なし別行立ては `\[...\]` を基本とする。
後で参照する式には equation 等と意味のあるラベルを使う。
ソースでは句読点後や数式の前後で適度に改行するが、空行で段落を増やさない。
日本語と数式の間の改行によって空白が変わる場合があるため、既存クラスで出力を確認する。
英文用の「すべての数式を独立行へ」という整形規則を日本語に機械適用しない。

新規の文献管理では biblatex/Biber を候補とし、既存の BibTeX と混ぜない。
cleveref を使うなら参照名を日本語で設定し、hyperref の後に読み込む。
著者名、所属、AI利用に関する本人確認、文献メタデータを推測で補わない。

段落IDがある原稿ではIDを維持する。抽出した補題などに既存IDを重複させない。
ID設定・ID指定編集・タグ付き原稿の投稿準備は、利用可能な latex-paragraph-ids の手順を使う。
そのスキルが使えない場合もIDを壊さず、必要な設定情報が不足する箇所を明示する。
投稿版の表示タグ除去は作業版の本文や段落境界を変えず、投稿依頼の範囲で行う。

ビルドは対象文書のルートと実際のエンジンで行い、エラー、未解決参照、引用を確認する。
図式、表、日本語字形、はみ出しなどに視覚上の疑問があるときは関連ページを表示して確認する。
見栄えだけの改ページや余白調整を増やさない。ビルド成功を数学の検証結果として報告しない。
