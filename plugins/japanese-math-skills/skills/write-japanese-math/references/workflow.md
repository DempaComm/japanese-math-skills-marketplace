# 執筆と改稿の手順

## 通常の作業

依頼から対象、範囲、読者、主張、長さ、保持する著者の表現を把握する。
新規文書は問題、到達点、必要な節を組み立て、既存原稿は先にその構造を読む。
判断済みの事項を再び承認待ちにしない。著者の概略説明を確定稿の引用文として扱わない。

改稿では依頼範囲を最後まで扱い、用語、参照、記号、節の接続を点検する。
限定修正で別節の本質的変更が必要になったときは、その依存を明示して範囲外の変更を保留する。
既存の作業記録を使い、小さい修正に全論文用の台帳を新設しない。

## 独立レビューを依頼された場合

別エージェントの利用が明示された場合だけ、read-japanese-math の手順に従う。
一回の許可は、比較・反復が明示されていなければ一回のレビューを対象とする。
凍結した原稿版、許可入力、想定読者、詳しさの契約を用意する。
原稿、コーパス、私的台帳を無差別に共有しない。

返却報告を全文読み、各指摘に ID を付ける。観察、診断、提案を区別し、同じ原因の指摘を修正単位へまとめる。
各指摘を漏れなく一つの単位へ対応付け、次のいずれかを記録する。

- `implement` は診断と修正を採用する。
- `modify` は読者の負担を認め、別の方法で修正する。
- `reject` は既存本文や有効な詳しさの契約を根拠として閉じる。
- `defer` は未解決として残し、必要な判断を明示する。

原判定と対象版は書き換えない。修正と自己点検によって独立レビューの FAIL を PASS に変更しない。
改稿後は参照、周囲の論理、規約を確認する。追加の独立差分レビューは別途依頼された場合に行う。
差分 PASS を原稿全体の PASS と報告しない。

## 検証と完了

診断の警告は点検の入口であり、語数や警告数をゼロにすることが目的ではない。
文章の役割を確認してから必要な変更をする。適切な専門語を警告のためだけに言い換えない。
変更に必要なビルドとホストの検査を行い、新しい変更や失敗がなければ不必要に繰り返さない。
独立レビューを行わない場合は執筆者側の点検であることを正しく報告する。
未解決の範囲内の問題があれば完了扱いにせず、その対象を示す。
